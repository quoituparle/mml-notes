Chapter 1 · Introduction and Motivation

What machine learning is, and why a book about maths is where you start.

Three ideas: data, model, learning

Machine learning is about designing algorithms that automatically extract valuable information from data. "Automatically" is the point: general-purpose methods that work on many datasets. Everything rests on three concepts:

Data

Numbers we feed in. We treat each example as a vector and a table of examples as a matrix.

Model

A simplified description of the process that generated the data, e.g. a function from inputs to real-valued outputs.

Learning

Tuning the model's parameters by optimisation so that it does well on the task. Like climbing a hill to its peak.

A model learns if its performance on a task improves after it sees data (the book paraphrases Mitchell). The real goal is generalisation: doing well on data it hasn't seen. Doing well on the training set alone may just mean the model memorised it.

Why maths? You can already use ML software without it. But the maths lets you understand what's under the hood, build new methods, debug existing ones, and know their hidden assumptions and limits.

Words are slippery

The book warns early that the same word means different things in different places. Two examples worth keeping in mind:

  • "Algorithm" can mean a predictor (a system that makes predictions from input) or the training procedure that adapts the predictor's parameters.
  • "Vector" has three views: an array of numbers (computer science), an arrow with direction and length (physics), or anything you can add and scale (mathematics). Chapter 2 uses all three.

Two ways to read

  • Bottom-up: start with foundations and build upward. You can always rely on what you've learned, but motivation can be thin ("why do I need eigenvalues?").
  • Top-down: start from a goal (say, PCA) and drill down to what it needs. You always know why, but the foundations can feel shaky.

Most people mix the two. These notes lean bottom-up, but every chapter has an "ML link" box so you can see where each idea gets used. Chapters in Part I mostly build on each other in order (2 → 3 → 4, then 5 and 6, then 7).
